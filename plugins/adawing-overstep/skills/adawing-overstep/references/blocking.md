# 停下等待时的执行细则

只在两种情况下读本文件：判定命中**验收歧义**，或改动命中**不可逆**。判据在 SKILL.md，本文件只管判定之后怎么执行。

## [CLARIFY]

### 必须执行的动作

1. 先检索，再判断歧义类型，顺序不可换
2. 输出 `[SCOPE]`，下一步写“停下澄清”
3. 输出 `[CLARIFY]`，附检索证据：查了什么、读了什么、各候选的当前值、为什么无法定夺
4. 提出问题，等待答复；答复前不执行改变状态的操作

写不出检索证据，说明还没到该停的地方。检索让停下成为有成本的动作，这是防止多疑的主要机制。

### 输出格式

```markdown
[CLARIFY] 验收歧义：________________
检索证据：________________
1. ________________？
2. ________________？
```

提问优先用宿主原生的提问工具；不可用时（如子代理环境）直接用文字提问。

### 低成本豁免

改动限于单文件且完全可逆时，只有检索已确认验收目标唯一、或所有候选当前值与行为相同，才可不停下。用户指向单一目标但检索发现多个同等候选且值或行为冲突时，不能用低成本理由替用户选择。

### 常见误判

- **能写出两种说法不算歧义。** “调长超时”听着像客户端和服务端两种解释，但配置通常只有一处，先去查。
- **信息缺失不算。** 检索后有唯一最优候选就直接做，并写进 `[SCOPE]`。
- **交付物形态不算。** 只影响产出形态，不影响对不对。选最有用的默认值，写进 `[SCOPE]`，继续。
- **偏好类取舍不算，但可以问。** 两个方案都可行时可以提问，同时给出默认动作，没有回复就按默认执行。

## 不可逆 [CONFIRM]

### 必须执行的动作

动手前说明三件事，然后等确认：

1. **后果**：谁会因此坏掉。删既有公共方法要先查调用方，不凭“没人用了”的转述
2. **副作用**：数据形状变更影响的下游、契约变更影响的调用端
3. **回滚方式**：git ref、备份路径、反向迁移；写不出回滚方式的改动不开始

```markdown
[CONFIRM] 不可逆：________________
后果：________________
副作用：________________
回滚：________________
```

### 为什么限定在“既有”对象

绿地项目的技术选型、新建表的字段设计不在不可逆之列，那是取舍，写进 `[SCOPE]`。把新建当成不可逆，会把需要发散的场景全部堵住。

区分方法：改动的对象在本次任务之前是否已有消费者。有，算不可逆；没有，算取舍。

### 目标不存在时

检索发现用户点名的方法、字段或文件不存在时，仍按不可逆处理。此时“后果”一栏写实际存在的是什么、真实调用方有几处，然后问清用户指的是哪一个。
