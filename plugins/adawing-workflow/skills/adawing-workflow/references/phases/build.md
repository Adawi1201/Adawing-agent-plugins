# build 阶段

build 负责按已确认范围实施改动，并在影响面扩大或证据不成立时及时停下。它不重新决定需求，也不负责提交分支。

## 开始前

- 读取当前 tier 的 plan 或 micro 范围声明
- 检查 git 状态，识别并保留用户已有改动
- 读取本任务目标文件及其调用方，不凭文件名猜实现
- 确认本轮要做的最小独立任务和对应增量验证

## 执行循环

对每个独立任务依次执行：

1. 只编辑当前任务需要的文件
2. 立即运行最相关、成本最低的增量验证
3. 阅读结果，确认失败或通过的真实含义
4. 对照 diff 检查范围、意外格式化和用户改动
5. 记录证据后再进入下一个任务

不要先批量改完再统一验证。不要顺手重构计划外代码、批量格式化无关文件或覆盖不属于本任务的更改。

## 偏离处理

- 需要新增计划外文件：先说明原因并更新范围
- 新增影响命中更高 tier：立即升档，补做缺失阶段
- 计划中的路径、接口或验证命令不存在：暂停当前任务，修正 plan
- 同一方案连续失败两次：停止重试，报告证据，回到 invoker 判断
- 验证暴露新的独立缺陷：记录为后续事项，不在当前任务中静默扩展范围

工具退出成功只说明工具执行成功。代码行为是否正确必须交给对应测试、构建或运行时证据判断。

## 完成 build

build 结束时报告实际修改文件、每个增量验证的结果和任何偏离。随后进入 review，不直接声称整个任务完成。
