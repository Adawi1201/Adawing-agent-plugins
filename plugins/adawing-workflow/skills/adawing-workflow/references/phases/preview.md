# preview 阶段

仅当主入口已经把 preview 判为 `compact` 或 `artifact` 时读取。preview 用于让验收对象可见，不承担需求论证、技术选型或额外审批。

## compact

适用于少量状态、输入输出或短流程即可表达的改动。直接在 plan 或当前消息中呈现：

- 关键状态的前后对照
- 代表性的输入和输出
- 必要的状态流或交互顺序

不创建文件，不重复完整计划，不展示与验收无关的状态。

## artifact

仅用于多页面、多状态或验收高度依赖视觉 / 流程的任务。生成：

`docs/adawing/previews/YYYY-MM-DD-<topic>/index.html`

约束：

- 一个主题只有一个入口页，用分区呈现关键状态
- 复用项目现有视觉语言和资源，不搭建第二套应用
- 不安装依赖，不复制业务逻辑，不伪造完整后端
- 只实现足以判断验收的代表性内容
- 文本、状态和交互不得因 viewport 变化互相遮挡

## 上下文成本

产物生成后只报告路径、覆盖的状态和未覆盖范围。不要把完整 HTML 贴入对话，也不要为了总结再次读取整个文件。需要验证时只检查相关片段、渲染结果和关键交互。

preview 完成后回到当前 tier 的同一个闸门。它不单独要求一次确认；`micro` 无闸门时按 micro 规则继续。
