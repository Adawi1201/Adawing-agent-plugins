# review 阶段

review 在 build 后、verify 前检查实际 diff。目标是发现行为偏差和不必要复杂度，不是为产生审查文档而复述改动。

## 审查范围

**范围**

- 实际文件是否与声明和 plan 一致
- 是否混入无关重构、批量格式化或用户改动
- tier 是否仍覆盖真实影响面

**行为与一致性**

- 调用方、公共接口、类型和数据形状是否同步
- 错误、空值和边界路径是否与验收一致
- 测试、文档和配置是否与实现一致

**简化**

- 删除未使用的导入、变量和分支
- 合并任务内新产生的重复逻辑
- 用提前返回降低不必要嵌套
- 移除没有当前需求支撑的抽象

**风险**

- 是否遗漏运行时验证、回滚路径或安全门控
- 是否把构建通过误当成行为正确

## 处理结果

小范围、不会改变已确认行为的修正可以直接处理，随后重跑对应增量验证。需要改变接口、数据形状、计划或 tier 的问题不得在 review 中暗改，必须回到相应阶段。

报告发现、已修正项和剩余风险。没有发现时明确报告“无 review 发现”，不可省略 review 结论。
