# AGENTS.md 内容取舍指南

## 判断标准

一条内容值得写入，需要同时满足：

- **推断不出来**：读仓库得不到，或要试错几轮、实际运行才能发现
- **长期成立**：与具体任务和当前进度无关
- **经常用到**：大多数任务都可能涉及
- **工具管不了**：lint、format、CI、类型检查、测试拦不住

能改代码或配置让错误不可能发生的，优先改代码或配置（加测试、加 lint 规则、加 hook），而不是写一条提示词。

## 七层内容

按从全局到局部的顺序排列，便于读者先建立整体认识。

### 1. 项目定位与技术栈

**写什么**：一句话定位；语言、框架及**确切版本号**；关键中间件。
**为什么**：版本决定生成代码时用哪套 API（如 Spring Boot 2 与 3 的 `javax` / `jakarta` 差异）。

### 2. 模块地图

**写什么**：顶层目录的职责边界、模块间依赖方向、跨模块通信方式、改 A 必须同步 B 的联动关系。
**不写什么**：文件清单、类清单，模型可以自己检索。

### 3. 可执行命令

**写什么**：构建、测试（含单个测试的过滤语法）、本地启动、检查。重点写看起来对、实际不对的命令，以及运行前提（如必须先启动数据库）。
**要求**：调研时实际运行过；未运行的标注“未验证”。

### 4. 非默认的代码约定

**写什么**：工具拦不住、在 code review 中会被打回的约定，例如异常处理策略、日志规范、分层命名、数据库规范。
**不写什么**：lint / format 已强制的规则（只写检查命令）；“写可读的代码”这类通用要求。

### 5. 项目特有的行为约束

**写什么**：只对这个项目成立的流程要求，例如改 `legacy/` 前必须先问、发版前必须跑某个脚本、某类改动必须附迁移脚本。
**不写什么**：通用的 agent 行为规则（遇到不清楚先提问、未验证不声称完成、不擅自提交）。这些由 agent 自身或已安装的 skill 管理，写进项目文件会重复，还可能与之冲突。

### 6. 红线与禁区

**写什么**：冻结或遗留目录、生成代码目录、密钥与配置纪律、数据库迁移纪律。
**为什么**：这类错误的代价远高于普通 bug。必须严格阻止的操作，同时用工具层（如 Claude Code 的 `permissions.deny` 或 hook）强制，提示词只作说明。

### 7. 领域术语表

**写什么**：业务术语与代码实体（表名、类名、字段名）的映射，以及容易混淆的概念。
**为什么**：业务说法是模型只靠代码最难对齐的信息。

## 负面清单

| 内容 | 原因 |
|---|---|
| 当前进度、临时 TODO、最近修的 bug | 很快过期，过期后误导模型 |
| 时间戳、“最近更新于” | 对模型没有价值 |
| 完整的文件、类、接口清单 | 模型可自行检索，且很快过时 |
| 长篇背景介绍、项目宣传 | 每轮占用上下文，没有可执行信息 |
| 模型已知的通用知识 | 如“React 是组件化框架” |
| 通用的 agent 行为规则 | 由 agent 或 skill 管理，重复且可能冲突 |
| 工具已强制的规则 | 重复；写检查命令即可 |
| 错误或决策的经过 | 只写约束本身；经过留在 git 与提交信息中 |

## 写法

- 每条一行，祈使句；原因不自明时，在同一行用一句话说明
- 写成可核验的形式：“缩进 2 空格”而不是“格式规范”，“提交前运行 `make lint`”而不是“注意代码质量”
- 同一行为只写一处，避免互相矛盾的规则；与其他指令文件冲突时，模型可能任选其一

## 示例

**坏**：

```markdown
## 项目介绍
本项目是一个现代化的、采用微服务架构的订单管理系统，致力于为用户提供
高效便捷的订单处理体验。项目始建于 2023 年，经过多次迭代……
```

问题：宣传语、历史沿革、无版本号，没有可执行信息。

**好**：

```markdown
## 项目概况
- 定位：订单中台后端，对外提供订单创建 / 查询 / 取消 API
- 技术栈：Java 17 + Spring Boot 3.2 + MyBatis-Plus 3.5 + MySQL 8 + Redis 7
```

**坏**：

```markdown
## 工作方式
- 需求不清晰时先提问，不要自行假设
- 请编写高质量的代码，注意边界情况
```

问题：通用规则，模型默认就会；第一条还可能与 agent 的提问策略冲突。

**好**：

```markdown
## 命令
- 单测：`pnpm test:unit`（`pnpm test` 含 e2e，需要先 `docker compose up api`）

## 代码规范
- 业务异常统一抛 BizException，由 GlobalExceptionHandler 转换响应，Controller 中不写 try-catch
```

## 体量

AGENTS.md 每轮都会注入上下文。文件越长，占用越多，遵循度也越低。Claude Code 文档建议单个文件控制在 200 行以内；只与部分代码有关的内容，放到模块目录下的 AGENTS.md（Claude Code 还可用 `.claude/rules/` 按路径加载）。导入（`@path`）能帮助组织文件，但不会减少上下文占用。
