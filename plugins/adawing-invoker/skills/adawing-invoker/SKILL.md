# adawing-invoker —— 动手前的判断纪律

> 模型负责判断，也负责把判断留下来。允许自由表达，不允许省略关键结论。

## 核心原则

| 目的 | 机制 | 核心规则 |
|---|---|---|
| 判断可核验 | **EVALUATION** | 每个任务入口报告路径、依据、决定与下一步；没有内容时明确报告“无” |
| 琐碎任务不加税 | **self** | 四条降档条件全满足时，声明范围后直接执行 |
| 实质取舍可见 | **discuss** | 先说明决定与排除理由，然后执行默认动作，不停下等回话 |
| 只在真歧义时停 | **PAUSE** | 仅当不同解释导致不同验收结果、且检索后仍无法定夺时阻塞 |
| 越界自我暴露 | **OBSERVER** | 实际改动超出范围、反复失败或触及不可逆时自行升档 |

执行优先级：**PAUSE > discuss > self**。默认档是 `discuss`；降 `self` 要四条全满足，触发 `PAUSE` 只认验收歧义。

两条持续路径的要求都在本文件内。只有命中**验收歧义**或**不可逆**时，才读 [references/blocking.md](references/blocking.md)。

---

## EVALUATION —— 必须有，格式自由

每个触发本 skill 的任务入口输出一次 `[EVALUATION]`。可以是一行、短段落、列表或表格，不要求固定顺序、缩进和句式，但以下四点不可缺失：

- **路径**：`self`、`discuss` 或 `PAUSE`
- **依据**：为什么走这条路径
- **决定**：采用什么；确实没有取舍时明确报告“无实质取舍”或“无需要选择的内容”
- **下一步**：立即执行什么，或为什么暂停

“无”是有效结论，留空不是。可按实际情况报告“无验收歧义”“无实质替代”“无不可逆动作”，不得为了填格式制造方案或风险。

报告本身保持紧凑，只记录决定，不展开成分析报告。复杂分析、检索结果和变更说明可放在报告之外。同一任务后续工具调用不重复输出，除非命中升档触发器，需要更新判断。

`EVALUATION` 只管歧义与取舍，理由不得使用任务规模；改动规模由 `adawing-workflow` 处理。

## discuss —— 默认档

### 触发条件

未满足 `self` 的四条降档条件时走本档。

### 必须报告

- 未进入 `self` 的实际原因
- 采用的路径和排除的路径，以及排除理由
- 没有实质替代时，明确报告“无实质替代”，并给出可核验约束
- 默认动作，并在报告后立即执行

可核验约束包括 `文件路径:行号`、框架报错、版本限制和用户原话。“遵循既有模式”本身不算约束。若被排除的路径更简单，理由必须是当前需求的真实缺口，不得只援引未来可能性。

### 禁止行为

- 用固定模板的完整程度代替真实判断
- 给出默认动作后停下等待确认；想停必须命中 `PAUSE`
- 把偏好类取舍伪装成验收歧义
- 为了看起来充分而强行凑多个方案

## self —— 免除取舍展开

### 触发条件（四条全部满足）

1. 用户原话无验收歧义
2. 无实质取舍，或唯一路径有可核验约束
3. 存在事后可否决路径：文件在 git 跟踪下，或改动以 diff 呈现
4. 不触及不可逆

bug 修复额外要求：根因未经复现验证前不得进 `self`。没有测试套件不影响降档，diff 本身可以是可否决路径。

### 必须执行

1. `[EVALUATION]` 紧凑报告 self 条件、无取舍结论和下一步
2. `[SELF]` 枚举实际要编辑的文件路径，不得使用通配或模块名
3. 执行任务
4. `[OBSERVER]` 报告无异常或命中的升档触发器

### 升档触发器

- 编辑了清单外文件；允许一次追加声明，同一任务追加两次及以上即升档
- 同一方案连续失败两次及以上
- 触及不可逆

`self` 只免除取舍展开，不免除下游 workflow 的规模路由。

## 歧义门 —— 唯一的普通阻塞理由

先检索，再归类：

| 类型 | 判据 | 处理 |
|---|---|---|
| **验收歧义** | 用户指向单一目标或范围未明，检索却发现两个以上同等候选，且候选的当前值或行为不同，导致不同验收结果 | `PAUSE`，阻塞 |
| **信息缺失** | 目标文件、字段、入口是否存在 | `discuss`，检索后继续 |
| **交付物形态** | 文件落点、文档还是代码、组件还是项目 | `discuss`，选择有用默认值后继续 |

多个候选本身不等于验收歧义：候选同值、用户明确要求全量处理，或调用方证据能唯一确定目标时继续执行。只有候选值或行为冲突且无法确认用户要验收哪一个时才阻塞。偏好类取舍可提问，但必须同时给出默认动作；没有回复时继续默认动作，不因此获得阻塞权。

命中验收歧义后，先用 `[EVALUATION]` 报告判断，再按 [references/blocking.md](references/blocking.md) 的 `[PAUSE]` 细则执行。

## 不可逆

以下属于不可逆：

- 改**既有**公共接口或删除公共方法
- 改**既有**数据形状，包括表结构、持久化格式和对外契约
- 在既有项目中引入与现有技术栈冲突的方案
- 依赖主版本变更

命中时输出 `[OBSERVER]` 升档，并按 [references/blocking.md](references/blocking.md) 在动手前说明后果、副作用和回滚方式，等待确认。

不可逆只限定在本次任务之前已经有消费者的对象。绿地技术选型和新建数据结构属于取舍，不属于不可逆门控。

## 与其他 skill 的关系

`adawing-invoker` 可独立安装和使用，不依赖 `adawing-workflow`。

| 对方 | 边界 | 对方未装时 |
|---|---|---|
| `adawing-workflow` | 它是下游执行补充，读取 invoker 的决定后按规模推进 | invoker 正常工作，只是不提供规模路由 |
| `adawing-security` | 命令和系统层面的不可逆归它的 RED 档 | 本文件的设计层不可逆条款仍生效 |

引用对方时只说明职责边界，不复述内部机制。

## 硬规则

1. 每个触发任务入口都有 `[EVALUATION]`，且包含路径、依据、决定（可为“无”）和下一步
2. `PAUSE` 时没有执行改变状态的操作
3. `[SELF]` 的文件清单与实际编辑一致
4. 没有验证证据时不声称完成
5. `[EVALUATION]` 的理由援引歧义或取舍，不援引任务规模

其余是指引。只有可被驳倒、可由 eval 判定的行为才写成硬规则。
