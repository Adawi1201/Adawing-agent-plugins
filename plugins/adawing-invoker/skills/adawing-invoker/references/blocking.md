# 阻塞路径的执行细则

只在两种情况下读本文件：判定命中**验收歧义**、或改动命中**不可逆**。默认路径（`self` / `discuss`）不需要它 —— 那两档的全部要求都在 SKILL.md 内。

**判据不在这里。** 是不是验收歧义、是不是不可逆，SKILL.md 已经判完了。本文件只管判完之后怎么执行。

---

## PAUSE

### 必须执行的动作

1. 先检索，再判断是哪一类歧义 —— 顺序不可换
2. 确认是验收歧义后，输出 `[PAUSE]`
3. **附检索证据**：grep 了什么、读了什么、各候选的当前值是什么、为什么没能定夺
4. 提出问题，等待答复；在此之前不动生产代码

检索本身有价值，也让阻塞变成有成本的动作 —— 这是防多疑的主要机制。写不出检索证据，说明还没到该停的地方。

### 输出格式

```markdown
[PAUSE] 验收歧义：________________
检索证据：________________
1. ________________？
2. ________________？
```

提问优先用 harness 原生 AskUserQuestion；不可用时（如子代理环境）直接用文字提问，不要自拼问答模板。

### 低成本豁免

改动限于单文件且完全可逆时，即使命中验收歧义也不阻塞。选定一个解释、标注、直接做。

> 这种改动的往返成本高于返工成本。

### 常见误判

- **"能写出两个说法"不算歧义。** "调长超时"听着像客户端和服务端两种解释，但配置通常只有一处 —— 先去查。
- **信息缺失不算。** 目标文件/目录/字段是否存在，检索后唯一最优候选就直接做并标注；多个候选走非阻塞提问。
- **交付物形态不算。** 新建项目还是给一个组件、写文档还是写代码、落到哪个目录 —— 只影响产出形态，不影响对不对。选最有用的默认、标注、继续。
- **偏好类取舍不算，但该问就问。** 两个方案都可行、模型无立场时用 AskUserQuestion 提问，**同时给出默认动作**，无回应则执行默认。"除了歧义不许停下问"是误读 —— 该问就问，只是别停。

## 不可逆门控

### 必须执行的动作

动手前说明三件事，然后等确认：

1. **后果** —— 谁会因此坏掉。删既有公共方法要先查调用方，不许凭"没人用了"的转述
2. **副作用** —— 数据形状变更影响的下游、契约变更影响的调用端
3. **回滚方式** —— git ref、备份路径、反向迁移；写不出回滚方式的改动不许开始

命中不可逆时同步输出 `[OBSERVER]` 升档，即使当前在 `self` 档。

### 为什么限定在"既有"之上

绿地项目的技术选型、新建表的字段设计不在不可逆之列 —— 那是取舍，归 `EVALUATION`。把新建当不可逆，等于把该发散的场景全部堵死，也就退回到"能力退化成等用户决策"的老问题。

区分方法：**改动的对象在本次任务之前是否已有消费者。** 有 → 不可逆；没有 → 取舍。

### 目标不存在时

检索发现用户点名的方法/字段/文件根本不存在，**不降级为信息缺失** —— 意图仍是删既有公共方法，门控照走。此时「后果」一栏的内容变成驳倒前提：说明实际存在的是什么、真实调用方有几处，然后问清用户指的是哪一个。

> 「没人用了」是转述，不是证据。转述被检索驳倒时，这一轮的产出就是那份证据。
