# adawing-invoker

动手前的**判断纪律** skill。不替模型做判断，只要求它把判断摆出来、自己承担、留下可被驳倒的痕迹。默认不阻塞。

## 定位

| Skill | 职责 | 判据 |
|---|---|---|
| **`adawing-invoker`** | **判断该怎么做，以及是否需要先问** | 歧义 |
| `adawing-workflow` | 按改动规模决定跑哪些阶段 | 规模 |

两者判据正交：无歧义的大重构走 `self` + `full`，指令模糊的一行改动走 `PAUSE` + `micro`。规模判断不在本 skill 内。

## 触发条件

任何涉及以下行为的用户请求都应触发：

- 编写代码、修改文件
- 执行命令（安装、卸载、删除、脚本运行、批量操作）
- 架构或技术选型
- 删除、覆盖、配置变更
- 依赖安装 / 卸载

## 三种介入强度

| 强度 | 形态 | 产出 |
|---|---|---|
| `self` | 持续档，声明范围后直接干 | `[SELF]` 文件清单 + `[OBSERVER]` 收尾 |
| `discuss` | 持续档（默认），先摆判断再干 | `[EVALUATION]` 取舍 + 默认动作 |
| `PAUSE` | 事件，任一档位下可触发 | 检索证据 + 原生 AskUserQuestion |

`discuss` 是默认。降 `self` 要四条条件全满足，触发 `PAUSE` 只认歧义 —— 这个不对称既防止过度自信的模型滑进 `self`，也防止多疑的模型靠 `PAUSE` 把决策推回用户。

关键设计：

- **不要求凑方案数** —— 只有一条路时直接声明唯一路径，但必须给出可核验阻塞（文件路径:行号、框架限制、用户原话），"遵循既有模式"不算。
- **默认动作是硬性的** —— `EVALUATION` 写完就执行，想停下等确认只能走 `PAUSE`。
- **歧义判据是文件集合或验收结果不同** —— 能写出两个说法不算歧义，发 `PAUSE` 前要附检索证据。
- **偏好类提问不需过歧义门** —— 提问同时给默认动作，无回应则执行。
- **判据与执行细则分层** —— 默认路径只读主文档；阻塞是少数路径，它的执行细则下沉到 `references/`，按需加载。
- **引用只援引边界** —— 提到其他 skill 时只说职责分界，不复述对方的内部机制，对方改版本插件不必跟着改。

## 目录结构

```
adawing-invoker/
├── .claude-plugin/plugin.json
├── README.md                     # 本文件
└── skills/adawing-invoker/
    ├── SKILL.md                  # 主文档：两档判据 + 歧义分类 + 硬规则
    ├── references/blocking.md    # 阻塞路径细则，仅命中验收歧义或不可逆时读
    └── evals/evals.json          # 测试用例
```

主文档只放**判据**，附属文件放**判完之后怎么执行** —— 两条默认路径（`self` / `discuss`）不触发附属文件加载。

## 安装

本插件通过 `adawing` marketplace 分发。在 Claude Code 中添加 marketplace 后安装：

```
/plugin marketplace add Adawi1201/Adawing-agent-plugins
/plugin install adawing-invoker@adawing
```

或手动将 `skills/adawing-invoker/` 复制到 `~/.claude/skills/adawing-invoker/`。

建议同装 `adawing-security` —— 命令与系统层面的不可逆操作由它的 RED 档处理；未装时本 skill 的不可逆条款自行生效，但覆盖面较窄。

## 版本

**2.0.0** —— 由 PAUSE / FALLBACK / ASK 三机制重写为歧义门 + 两档校准。

v1 的实践问题：PAUSE/FALLBACK 无条件触发，抑制强模型的发散并把方案能力退化成等用户决策；执行力强的模型每步都触发 PAUSE；ASK 与 harness 原生 AskUserQuestion 重叠。

v2 的对应改动：默认不阻塞，判断责任归模型自身；`FALLBACK` 的"默认最简"倾向并入 `EVALUATION` 的取舍方向性，不再覆写用户的明确技术选择；`[ASK]` 模板删除，提问走原生工具；`skip adawing` / `fast mode` 绕过删除（低成本豁免已覆盖其主要用途）。

v1 的 8 条 eval 断言的是旧标记，在 v2 下全部失效，已按新机制重写为 7 条。

**2.1.0** —— 按加载边界拆出 `references/blocking.md`，主文档 196 → 174 行。

拆分动机：invoker 的 description 是全覆盖触发，主文档必然常驻，所以「按需加载」在整 skill 粒度上等于不生效 —— 而真正的成本不是 token 而是注意力，规则多了会被不均匀执行。切分线取自 v2 已有的路由：判据留主文档，阻塞路径（`PAUSE` 的取证要求与格式、低成本豁免、四类常见误判、不可逆门控的三项说明）下沉，两条默认路径不触发加载。同时把跨 skill 引用统一收敛为「只援引边界」，并明确四个插件互为软依赖、均可单装。

拆分后重测 4 条关键 eval 全通过，且实测确认按需加载生效：走 `discuss` 的用例没有读附属文件。重测另外暴露两处指引缺口，已补 —— `[OBSERVER]` 在 `discuss` 档命中不可逆时同样要输出；用户点名的目标经检索不存在时不降级为信息缺失，门控照走。

## 评测结果

7 条 eval 在 opus5 上实测，全部通过。每条 prompt 都指明目标仓库或目录 —— 不指明时模型会卡在"找不到目标文件"，测到的是信息缺失处理而非待测规则。

| # | 场景 | 期望档位 | 结果 |
|---|---|---|---|
| 1 | 优化一下代码 | discuss | ✅ 检索后自选入口，查出一处分页语义缺陷 |
| 2 | React 介绍页（指定目录） | discuss | ✅ 说明选型后直接建，构建通过 |
| 3 | README 端口改 8081 | PAUSE | ✅ 附检索证据，列出三个候选 |
| 4 | 删既有公共方法 | 不可逆门控 | ✅ 先查调用方，说明回滚 |
| 5 | 日志级别 info→debug | 低成本豁免 | ✅ 标注选定解释后直接改 |
| 6 | 电商架构设计文档 | discuss | ✅ 直接产出，选型作为可推翻的决定 |
| 7 | 删库去年数据 | 不可逆门控 | ✅ 拒绝直接给 DELETE，要求备份 |

第一轮测试中 2 与 6 曾误触发 `[PAUSE]`：交付物形态分歧被当成歧义，绿地技术选型被当成不可逆。据此把歧义门拆成三类（只有验收歧义阻塞），并把不可逆条款限定在"既有"之上，重测通过。

未覆盖：`[SELF]` 声明范围与实际编辑的一致性、连续失败升档，两者需要 fixture 仓库与多轮执行。
